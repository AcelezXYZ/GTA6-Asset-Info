# 1. RPF9 archives

*Part of the [SixNG format specification](README.md). Numbers as of 2026-11-20; confidence: confirmed / inferred / unknown.*

## Header (0x40 bytes)

| Off | Size | Meaning | Confidence |
|-----|------|---------|-----------|
| 0x00 | 4 | magic `39 46 50 52` (`"9FPR"` on disk, `RPF9` as a LE u32) | confirmed |
| 0x04 | 4 | `toc_end`: absolute end of the TOC; data starts after it | confirmed |
| 0x08 | 4 | varies | unknown |
| 0x0C | 4 | `names_size`, size of the name block inside the TOC | inferred |
| 0x10 | 8 | per-archive hash or salt | inferred |
| 0x18 | 4 | constant 0x47A00 | unknown meaning |
| 0x1C | 4 | constant 0x150 | unknown meaning |
| 0x20 | 2 | 3..7 (version or level?) | unknown |
| 0x22 | 2 | 1 | unknown |
| 0x24 | 4 | entry count | inferred |
| 0x28 | 4 | `key_id`: one of 4 values across the install | inferred |
| 0x2C | 4 | flags `01`/`02 0f 09 00` | unknown |
| 0x30 | 4 | constant 0x10 | unknown |

## TOC (0x40 .. `toc_end`)

**Encrypted** (confirmed). Entropy is at the uniform-random level and there
are no repeated 16-byte blocks. **There are no file names or directory tree
from the archive itself.**

## Payload (confirmed)

- Not encrypted. Every file body after the TOC is one or more plain **zlib**
  streams (`78 DA`), each on a 16-byte boundary.
- RAGE resources start at a **4 KiB boundary + 0x10**.
- Plain files (XML, PSO, …) are split into 64 KiB chunks, each its own zlib
  stream that inflates to exactly 65,536 bytes (except the last).

## Carving index (how SixNG lists an archive)

1. Try every 16-byte offset after `toc_end` for a zlib header and inflate
   it (streamed, in parallel segments, checkpointed so a run can resume).
2. Drop streams that overlap an earlier one.
3. Join contiguous streams (the next starts at the 16-aligned end of the
   previous) into one entry when the previous stream inflated to exactly
   65,536 bytes, when the new stream does not look like a file start, or
   when it looks like a RAGE object but is **not** at 4 KiB + 0x10 (large
   resources store a page as several streams, [§2](02-resources.md)).
4. Classify by the first bytes: `resource` (PRD0 tag), `rageobj` (pointer
   `0x5…` at +8), `xml`, `pso` (`PSIN`), `rbf` (`RBF0`), `gfx`, `dds`,
   `png`, `text`, `bin`.
5. Name pass: find `name.#xx` strings in each system page ([§2.3](02-resources.md)).

On `levels.rpf` (over 50 GB) this finds about 1.1 M streams covering 98.3 %
of payload bytes; the rest is padding.
